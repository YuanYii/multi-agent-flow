| 分支类型 | 触发特征与指令 | 处理机制与响应契约 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **分支 A：系统控制台操作** | `/yy-flow help`<br>`/yy-flow start`<br>`/yy-flow status`<br>`/yy-flow kanban`<br>`/yy-flow sync-pr` | **直通底层运维引擎**（0 前置分级），直接执行对应脚本并输出系统状态。 | 查看帮助手册、初始化 SOP、启动看板、大盘巡检、PR 解阻 |

## 二、 业务需求【分级三问】决策流

```text
[业务需求输入]
   │
   ├─► 1. 会留下代码/文档/配置等仓库文件修改吗？
   │      ├─ 否 ──► 2. 结论需要作为后续工程依据事后追溯吗？
   │      │            ├─ 否 ───────────────► 【L0 即时问答】（无卡直接作答，0 毫秒 CLI 延迟，草稿入草稿箱）
   │      │            └─ 是 ───────────────► 【L1 轻量任务】（建单停步待开工：B/C/D/F/G）
   │      │
   │      └─ 是 ──► 3. 需要多角色协作、修改核心业务代码或变更公共基础库吗？
   │                   ├─ 否 ───────────────► 【L1 轻量任务】（建单停步待开工 → 待人类授权后单角色完成）
   │                   └─ 是 ───────────────► 【L2 标准研发任务】（建单停步待开工 → 待人类授权后多角色协同）
```

## 三、 单一职责原则 (SRP) 网关前置强门禁与单轮对抗性质询回环

- 凡属于 L1/L2 业务需求，网关强制执行单一职责审查与**单轮对抗性提问回环 (One-Pass Adversarial SRP Loop)**。
- 一张任务卡必须且仅能由一位专属专家负责，产出单一形态的原子交付物（工时 ≤ 8.0h）。
- 若需求涉及跨正交领域（如既有后端接口又有前端页面、既有架构设计又有业务编码），网关强制直接触发 PM 严经理按原子工作包拆解建卡，严禁单卡承接复合全栈需求。

### 单轮对抗性提问回环流程 (One-Pass Adversarial Loop)

在初次 WBS 拆单后，必须强制执行一轮蓝军挑刺质询，形成防粗粒度复合大卡的回环门禁：

1. **Pass 1 初次拆解**：PM 针对输入需求拆出初始候选任务列表；
2. **蓝军对抗挑刺四问质询**：针对每个候选任务，强制进行批判性审查：
   - **Q1 (交付可验性)**：是否存在可先行独立合入、独立单测的阶段性交付物？（若存在 → 判定可拆分）
   - **Q2 (依赖并行性)**：是否有成果可先行产出并解锁下游角色（如 Mock 契约先行）？（若存在 → 判定可拆分）
   - **Q3 (失败隔离性)**：子模块测试打回是否会导致不相干代码连带回滚？（若存在 → 判定可拆分）
   - **Q4 (动作单一性)**：是否隐含多动词或工时明显 > 4.0h？（若存在 → 判定可拆分）
3. **Pass 2 二次细拆与单轮即止**：
   - 判定 `PASS` 的任务保留；
   - 判定 `CHALLENGED` 的任务执行**仅限一次**的二次细拆为原子子卡；
   - **回环即刻终止**：细拆产物直接固化，严禁无限递归，确保任务颗粒度适中。
- **执行态 Task ID 豁免**：指令若显式携带明确 Task ID（如 `T0001`）或属于子代理内部流转，直接穿透网关进入状态机推进，严禁二次建卡。
- **开工授权硬红线（/yy-flow auto 显式自动化指令除外）**：建卡完成即达成本次规划会话终态，任务卡必须严格停留在【待开始】状态；未经人类用户显式下达开工授权指令（如“开工”、“开始开发”、“确认执行”），严禁自动派单推进至【进行中】。
