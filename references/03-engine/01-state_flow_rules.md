# 03-状态流转与防错门控规约 (State Machine & Anti-Error Spec)

## 一、 6 大状态跃迁合法矩阵

| 起始状态 | 目标状态 | 合法操作人 / 角色 | 核心门禁与前置条件 |
| :--- | :--- | :--- | :--- |
| **待开始** | **进行中** | 任务 Assignee | 认领任务，检查工作区与分支就绪 |
| **进行中** | **审查中** | 李开发 / 马前端 | 代码编写完毕，本地单元测试全部通过 |
| **进行中** | **已完成** | 钱架构 / 李文通 / 吕改特 | L1 轻量任务或单角色任务交付物就绪 |
| **进行中** | **已阻塞** | 任务 Assignee / Dispatcher | 遇到外部依赖未就绪、超时熔断或权限不足 |
| **已阻塞** | **进行中** | 任务 Assignee / Dispatcher | 依赖解除、PR 合流自动解阻或换引擎重新派发 |
| **审查中** | **测试中** | 周审查 | 代码审查通过，质量合规，静态扫描无告警 |
| **审查中** | **已退回** | 周审查 | 发现代码缺陷、边界未覆盖或规范不合规（附带打回原因） |
| **测试中** | **已完成** | 章测试 | 集成测试通过，边界用例覆盖完毕，质量准出 |
| **测试中** | **已退回** | 章测试 | 测试发现缺陷，附带测试报告与复现步骤退回修改 |
| **已完成** | **已验收** | PM 严经理 | 终态验收通过，工时与交付物完整核验 |
| **已退回** | **进行中** | 任务 Assignee | 收到打回意见，重新开始修改实现 |

---

## 二、 五层防错门控机制

1. **第一层：身份与角色校验**（操作人必须与任务卡 Assignee / Handler 身份匹配）；
2. **第二层：状态单向推进校验**（禁止非法越级跳转，如待开始直接跳已完成）；
3. **第三层：交付物与文档完整性断言**（阶段提审必须产出对应的代码或标准报告）；
4. **第四层：并发排他文件锁**（`file_lock.py` 确保多进程读写 board.json 时原子互斥）；
5. **第五层：结构化审计追踪**（每次流转强制追加 `user_data/logs/audit_trail.log`）。
