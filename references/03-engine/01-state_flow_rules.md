# 03-状态流转与防错门控规约 (State Machine & Anti-Error Spec)

> 本规范定义任务在 8 个标准状态间的跃迁规则、打回不拆单机制、五层防错门禁与终态核验门控。

---

## 一、 8 大标准状态跃迁合法矩阵

| 起始状态 | 目标状态 | 合法操作人 / 角色 | 核心门禁与前置条件 |
| :--- | :--- | :--- | :--- |
| **待开始** | **进行中** | 任务 Assignee / PM | 认领任务，检查工作区与分支就绪，原子分配并发槽位 |
| **进行中** | **审查中** | 李开发 / 马前端 | 代码编写完毕，本地单元测试全部通过，产出开发报告 |
| **进行中** | **已完成** | 钱架构 / 李文通 / 吕改特 | 特权/短链任务（B/C/D/F/G 或 [HOTFIX]）交付物就绪 |
| **进行中** | **已阻塞** | 任务 Assignee / PM | 遇到外部依赖未就绪、阻塞或等待外部确认 |
| **已阻塞** | **进行中** | 任务 Assignee / PM | 依赖解除、PR 合流自动解阻后恢复执行 |
| **审查中** | **测试中** | 周审查 | 代码审查通过，质量合规，静态扫描无安全告警 |
| **审查中** | **已退回** | 周审查 | 发现代码缺陷、边界未覆盖或规范不合规（生成 DEF 编号打回原负责人） |
| **测试中** | **已完成** | 章测试 | 集成测试通过，边界用例覆盖完毕，质量准出并记录 end_time |
| **测试中** | **已退回** | 章测试 | 测试发现缺陷，附带测试报告与复现步骤打回原负责人 |
| **已完成** | **已验收** | **人类用户 (USER) 专属** | **终态专属人类验收确认（严禁 Agent 触碰与代签；仅限 Web 看板或交互式 TTY 确认）** |
| **已完成** | **已退回** | 人类用户 (USER) | 验收不通过，退回原负责人重新修改 |
| **已退回** | **进行中** | 任务 Assignee | 收到打回意见，认领并开始返工修复（打回不拆单，原卡推进） |
| **任意合法态**| **已取消** | 严经理 (PM) / USER | 需求变更作废，必须填写取消原因 remarks 与 end_time（终态只读锁定） |

## 二、 【最高安全红线】人类专属终态验收原则

1. **绝对禁止 Agent 代签验收**：
   任何 Agent（包含 PM 严经理）严禁调用 `quick_task.py accept` / `accept-all`，严禁传入 `--delegated-by USER` 伪造人类代行凭据，严禁在自动化流水线中将任务推入【已验收】。
2. **自动化边界收敛**：
   所有 AI 专家的自动化执行到【已完成】即告终止，随后在回复中输出成果并提请人类用户核验。
3. **合法验收通道**：
   - 通道 A：人类用户在 Web 可视化看板中携带主控 Token 点击【验收】按钮；
   - 通道 B：人类用户在交互式终端执行 `python3 scripts/quick_task.py accept --task-id <ID>`（自带 TTY 检测与 [y/N] 二次确认）。

## 三、 打回不拆单规范与缺陷编号机制

1. **原卡就地流转**：
   当任务在审查中或测试中发现缺陷时，**绝对禁止新建子任务**（如 `T0001-fix`），必须由周审查或章测试将当前任务原卡置为【已退回】。
2. **处理人定向重置**：
   打回时，经办人（Assignee）强制重置为**任务初始负责人 (Owner)**，审查/测试专家严禁将经办人设为自身。
3. **结构化缺陷编号 (DEF-ID)**：
   打回必须生成全局唯一递增缺陷编号 `DEF-{TaskID}-{轮次}`（如 `DEF-T0084-1`），并记录缺陷描述与复现证据。

---

## 四、 五层防错门控机制

1. **第一层：身份与代行白名单校验**：操作人必须与 Assignee 匹配；跨角色代行严格遵循 `DELEGATION_ALLOW_MATRIX`；
2. **第二层：状态单向推进校验**：禁止非法越级跳转（如【待开始】直接跳【已完成】）；
3. **第三层：交付物与文档完整性断言**：提审必须有修改文件列表与开发报告，测试完成必须有测试报告与实际工时；
4. **第四层：并发排他文件锁**：`file_lock.py` 基于底层文件锁确保多进程原子互斥，杜绝脏写；
5. **第五层：结构化审计追踪**：每次流转强制追加 `user_data/logs/audit_trail.log`，操作可永久追溯。
