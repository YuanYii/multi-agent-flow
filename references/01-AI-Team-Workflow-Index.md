## 路由总表（Routing Table）

| 角色代码 | 抽象角色名称 | 触发源 (任务来源) | 任务完成流转点 | 准入/领取机制 |
|---------|-------------|------------------|---------------|--------------|
| **PM** | 项目经理 | 项目计划 / 阶段总结 | 分配 → `进行中`；验收 → `已验收`；E类快捷验收 → `已验收` | 严经理分配 / 主控 |
| **ARCHITECT**| 系统架构师 | PM 任务拆解 / 需求变更 | 完成 → `已完成` (提交 PM 验收) | PM 派发 (禁自领取) |
| **DEV** | 开发工程师 | 看板任务 / 工作包拆解 | 完成 → `审查中` (处理人=REVIEWER)；G类环境完成 → `已完成` | 可自领取 (并发≤3) |
| **FRONTEND** | 前端开发工程师 | 看板任务 / UI 工作包 | 完成 → `审查中` (处理人=REVIEWER)；G类前端环境完成 → `已完成` | 可自领取 (并发≤3) |
| **REVIEWER** | 代码审查员 | 看板 (状态=`审查中`) | 通过 → `测试中`；不通过 → `已退回` | 被动触发 |
| **QA** | 测试工程师 | 看板 (状态=`测试中`) | 通过 → `已完成` (带结束时间)；不通过 → `已退回` | 被动触发 |
| **DOCS** | 文档工程师 | 看板 / PM 分配 | 完成 → `已完成` (处理人=PM) | PM 派发 |
| **DEVOPS** | Git与运维管理员 | 阶段验收 + 总结完成 | 完成 → `已完成` (处理人=PM) | PM 派发 |

## 各角色核心职责与红线边界

### 1. 项目经理 (PM)
- **职责**：WBS 维护、工作包拆解、任务派发、进度风险预警、F 类阶段管理总结主笔、最终阶段验收。
- **红线**：❌ 不编写业务代码、不做技术架构设计、不亲自跑单测/集成测试。

### 2. 系统架构师 (ARCHITECT)
- **职责**：系统架构设计、技术选型、ADR（架构决策记录）编写、架构评估、F 类阶段技术总结主笔。
- **红线**：架构设计 ≠ 代码实现；架构设计任务完成直接提交 `已完成` 交 PM 验收。

### 3. 开发工程师 (DEV)
- **职责**：Schema 定义、Workflow/API/数据库编码实现、编写单元测试（ coverage > 80% ）、产出开发任务报告、G 类环境搭建与运维治理。
- **约束规则**：
  - ⚠️ 并发上限：最多同时 3 个任务处于 `进行中`；
  - ⚠️ 顺序限制：严格按任务编号从小到大依次处理；
  - ⚠️ 自领取限制：自领取时必须**先改状态为进行中确认落库后再开始编码**（严禁先干后补）。

### 3.5 前端开发工程师 (FRONTEND)
- **职责**：现代 Web 界面与组件开发、响应式布局与微交互实现、前端性能与可访问性自测、前端开发报告产出。
- **约束规则**：
  - ⚠️ 并发上限：与 DEV 一致，最多同时 3 个任务处于 `进行中`；
  - ⚠️ 顺序限制：与 DEV 一致，按任务编号从小到大依次处理；
  - ⚠️ 自领取限制：与 DEV 一致，**先改状态为进行中确认落库后再开始编码**（严禁先干后补）；
  - ⚠️ 提交流转：与 DEV 镜像 — 提交审查 `进行中 → 审查中`（处理人=REVIEWER）；G 类前端环境任务可走 `进行中 → 已完成` 直跳；
  - ⚠️ A 类前端任务的红线：禁止 `进行中 → 已完成` / `进行中 → 已验收` 直跳（须经审查+测试链路），与 DEV 同约束。

### 4. 代码审查员 (REVIEWER)
- **职责**：代码规范 (PEP8 / Clean Code)、安全漏洞扫描 (SQLi/XSS/Token泄露)、性能评估、Pydantic v2 规范。
- **报告规则**：审查报告需标注问题优先级（**阻塞** / **重要** / **建议**）；打回时回写结构化缺陷信息。

### 5. 测试工程师 (QA)
- **职责**：集成测试、端到端系统测试、性能压测、回归测试。
- **红线**：不做单元测试（单元测试由开发负责）；测试通过必须在看板中**强制填入结束时间**。

### 6. 文档工程师 (DOCS)
- **职责**：平台操作手册、API 帮助文档、技术总结报告维护。
- **流程特例**：文档类任务走精简流转 `待开始 → 进行中 → 已完成 → 已验收`（无需代码审查与测试）。

### 7. Git 与运维管理员 (DEVOPS)
- **职责**：阶段代码整理、分支合并 (`feature → stage → main`)、打 SemVer 标签、环境编排治理。
- **触发逻辑**：仅在当前阶段所有任务 `已验收` 且阶段总结 `已验收` 后，由 PM 分配触发。
