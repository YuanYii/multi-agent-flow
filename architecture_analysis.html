执行摘要与全景指标

multi-agent-flow 是一个面向 AI 多 Agent 与人类团队协同研发的高置信度、契约驱动型治理技能包。系统致力于消除 Agent 研发过程中常见的“越权代签、打回碎片化、状态悬挂、空头验收与 Git 串染”五大核心痛点。

01

六层分层架构体系

系统采用松耦合、高凝聚的六层垂直分层设计，各层具备严格的单向依赖契约：

第 1 层：统一入口网关协议 (Unified Gateway Protocol) Gateway Layer

统一收敛 Slash 指令（/yy-flow help, /yy-flow kanban 等）与日常自然语言需求。前置执行【分级三问】，输出 L0 即时问答、L1 短链任务、L2 标准研发判定，实现 0 毫秒 CLI 延迟的分流。

SKILL.md 分级三问网关 Task ID 豁免通道
第 2 层：角色拓扑与能力派生层 (Role Topology & Capability Layer) Agents Layer

8 位拟人化专家角色定义（YAML 驱动），结合 auto_scan_stack.py 自动嗅探目标项目架构技术栈，并通过 tech_capability_expander.py 动态派生各技术专家专属能力。

agents/*.yaml verify_and_export_agents.py agent_tech_overlay.py
第 3 层：规则约束与红线守卫层 (Rules & Constraints Layer) Rules Layer

声明式安全准则（SOUL.md 安全心脏、AGENTS.md 协同红线、USER.md 授权协议）与 6 大业务规范，确立“严禁 Agent 触碰【已验收】终态”与“无工单不 Git”物理防线。

rules/*.md references/*.md 十大协同红线
第 4 层：CLI 状态流转与门禁校验引擎 (CLI Engine & State Machine) Engine Layer

纯 Python 3 轻量引擎，提供原子级状态机流转（transition_task.py）、并发锁（file_lock.py）、代码变动与单测凭据闭环检验（validate_transition.py）、巡检大盘（heartbeat.py）。

transition_task.py quick_task.py _lib/core/*.py sync_pr_status.py
第 5 层：多端可视化看板与交互协作层 (Kanban & UI Layer) UI Layer

内置轻量 HTTP 服务（start_kanban_server.py，默认 32886 端口），支持数据表格、状态泳道、专家负载与阶段工作包 4 大视图，集成 Master Token 主控鉴权与局域网只读协同。

kanban/index.html start_kanban_server.py offline_board.html
第 6 层：数据持久化与文档资产层 (Persistence & Docs Layer) Data Layer

运行态数据完全私有落盘于 .yy-flow/user_data/（board.json、审计日志 audit.log、并发锁），交付文档规范化落盘于项目根目录 docs/D01~D06。

paths.py (多级解析) user_data/board.json docs/ 规范骨架

03

五层防错门禁与状态机

🛡️ 五层纵深防御体系 (Fail-Closed)
第 1 层 · 入口防错
分级三问网关
L0 即时回答零建卡，L1 短链单角色，L2 复杂任务强制走多专家全链。
第 2 层 · 运行时防错
角色越权强拦截
状态机校验发起人角色与流转方向，非法跃迁直接抛出 Exit(1) 阻断。
第 3 层 · 质量凭证防错
实体变更核验
推进至【已完成】必须绑定物理代码 Diff 或单测运行态 Log，杜绝纸面流转。
第 4 层 · 分支合流防错
Git 物理守卫
工作区存在未结项代码时物理阻断 git commit，提交信息禁止泄露内部虚拟人名。
第 5 层 · 终态防线
人类专属终验
【已验收】状态强绑定 TTY 交互与 Token，任何 Agent 子进程均被物理拦截。

核心 CLI 引擎与数据流

系统底层由高度模块化的 Python 架构驱动，遵循高容错与多环境自适应设计：

引擎模块 文件路径 主要职责与架构特征
数据根多级解析 scripts/paths.py --project-root > 环境变量 > .yy-flow 自定位 > CWD 多级回退，实现本地内嵌与全局共享安装的透明解耦。
并发安全文件锁 scripts/_lib/core/file_lock.py 跨平台基于 fcntl (Unix) / msvcrt (Windows) 的原子文件锁，杜绝多子代理并发读写 board.json 产生冲突。
门禁强校验器 scripts/_lib/core/validate_transition.py 集中化状态流转断言，执行阶段前置依赖、角色合法性、打回上限（≤2轮）与输出凭据校验。
多平台导出器 scripts/verify_and_export_agents.py 读取 agent_platforms.yaml，自动向 8 大宿主平台输出对应格式的 YAML/TOML/Markdown 子代理配置，并执行 Fail-Closed 格式断言。
巡检与大盘监控 scripts/heartbeat.py 统计交付周期 Lead Time、计算专家当前在制品（WIP）负荷，并探测滞留与阻塞告警。
05

架构优劣批判审视

✅ 突出架构优势 (Architectural Strengths)
  • 极低环境侵入性：纯标准库 + 极简依赖（PyYAML/python-docx），开箱即用，免配复杂数据库。
  • 确定性防御机制 (Fail-Closed)：将防错逻辑固化在 Python 代码与文件锁中，彻底摆脱纯 Prompt “提示词防线”的不稳定性。
  • 测试健全度极高：具备 355 项深度覆盖的自动化用例，保障状态机与核心引擎的重构安全性。
  • 多端多环境原生兼容：打通主流 IDE、CLI Agent 宿主与局域网 Web 看板，配置资产随 Git 迁移。
⚠️ 潜在瓶颈与设计局限 (Bottlenecks & Limitations)
  • JSON 文件锁高并发写瓶颈：在大规模并发子代理或超多工单场景下，频繁读写 board.json 存在文件锁等待开销。
  • 单层 Master Token 鉴权模型：看板目前无细粒度 RBAC 与独立用户账号系统，多成员协作依赖网络隔离与单主控口令。
  • 异构模型路由未在底层深度硬编码：各专家的模型档位主要依赖宿主或全局配置，未提供像 Anneal 那样的细粒度多模型多档位矩阵动态绑线。
  • 前端为单文件 Vanilla JS 架构：离线与单文件分发极佳，但若未来引入高阶甘特图/复杂拖拽，前端代码体积与维护复杂度会上升。
06

演进路线与重构建议

🚀 推荐演进方向与架构优化建议
P1 · 短期
存储引擎抽象 (SQLite 备选)
保留 board.json 作为默认轻量落盘，扩展 SQLite 适配器以支持百级并发工单的高吞吐场景。
P2 · 中期
多模型智能路由矩阵
在 workflow.config.yaml 中允许为 8 大专家指定不同模型（如架构/审查用强推理模型，编码用高速度模型）。
P3 · 长期
双盲独立评审机制扩展
在 L2 关键任务中引入类似 Anneal 的双审查员（Reviewer 1 + Reviewer 2）背靠背独立复核机制。
07

决策摘要与结论

📌 架构核心结论

multi-agent-flow 是一个工程成熟度高、安全防线严密且测试覆盖完备的 Agent 协同治理系统。其核心价值在于通过确定性的状态机门禁、代码级物理拦截与 8 专家制衡体系，将原本不可控的 AI 编码行为收敛到高置信度的企业级研发规范中。当前架构轻量敏捷，在当前单团队/中小型项目协作场景下运行平稳，未来演进重点可聚焦在异构模型按角色分流与高并发存储引擎增强。
