00

执行摘要与关键特征

Anneal 是一个在本地机器上运行的多 Coding Agent 自动化任务链中枢 (Autonomous Coding Agent Chain Harness)。其核心设计理念为 “你只写 spec，它清空看板 (You write the specs. It clears the board)”，旨在通过预先配置的 12 步多角色 Agent 链条，实现从需求规格到代码计划、跨模型双盲代码评审、独立环境回归测试、直至最终 Git 自动合流的全无人值守闭环。

01

运行时拓扑与 Monorepo 分层架构

Anneal 采用了经典的“Web 控制台 + 控制平面 API + 关系型持久层 + 外部 Runner 调度器 + 临时工作区”分布式拓扑：

1. 前端控制台 (Web Console · apps/web) React + Vite + Tailwind

提供多项目仪表盘、任务看板（Kanban）、Agent 角色定义、能力授权、运行态跟踪（Runs / SessionEvents）、审批流（Approvals）以及人机交互收件箱（Inbox）。

2. 控制平面 API (Control-Plane API · packages/api) Hono Framework

基于 Hono 框架构建的高性能服务端。负责处理任务生命周期流转、分发 Fenced Lease、鉴权校验（Operator/Runner/Session 三主体）、处理 Filesystem Grants 并管理集中式状态目录。

3. 持久化数据层 (Persistence Layer · packages/db) PostgreSQL + Prisma ORM

严格分离 Task 业务状态与运行态 Run / SessionEvent 时序事件流。持久化存储 Projects, Agents, Capabilities, Secrets (AES-256-GCM), Fencing Generations 与 Outputs。

4. 本地 Runner 调度守护进程 (Local Runner · packages/runner) Node.js Daemon

以带租约的世代号（Fencing Generation）轮询认领 Run。为每个任务动态创建临时的 Ephemeral Git Workspace（成功则销毁，失败保留配额）；预检（Preflight）本地 Codex / Claude / Pi 登录状态，并注入专用环境变量。

5. 会话级 MCP 扩展与 Inbox 仲裁 (Session Tools · packages/inbox) Stdio MCP Server

通过动态创建的 stdio MCP Server 为 Codex / Claude 注入 Anneal 专用工具，为 Pi 注入 Extension。Agent 在遇到阻断或需决策时，调用工具向 Web Inbox 提问，任务进入阻塞等待人类仲裁。

6. 合流执行器 (Merge Executor · packages/merge-executor) Merge Train Engine

当任务完成所有审查和回归后，通过 Merge Readiness 争抢 Merge Lease，并在 Merge Train 协调下自动完成主分支合并（通过 packages/github-client 联动）。

12 步全保证流水线 (Compound Engineer Workflow)

Anneal 的核心旗舰工作流为 12 步复合工程师链 (Compound Workflow)。其最大特点是跨异构模型编排（Claude Opus、GPT-5.6 Sol/Luna、Pi）与双盲独立审查机制：

03

租约防脑裂 (Fenced Lease) 与并发调度

在无人值守高并发场景下，Agent 子进程可能因为网络挂起、Rate Limit 或长时间执行而出现超时。Anneal 在控制平面与 Runner 之间设计了严密的带世代号租约控制 (Fencing Generation Mechanism)：

🔒 状态流转防脑裂与清理契约
  • Lease 租约认领：Runner 领单时，API 颁发带过期时间与 fencing_generation 递增号的租约凭证。
  • 世代号强校验：Runner 提交的每一次会话事件、中间产物、Inbox 请求和状态变更，API 均强校验 fencing_generation。若租约已被其他 Runner 抢占或过期，请求立即被 409 Conflict / 412 Precondition Failed 拒绝。
  • 进程组强杀清理：一旦检测到世代失效，Runner 会物理终结该 Provider 所在的操作系统进程组（Process Group），防止僵尸 Agent 持续写脏仓库。
  • Merge Train 串行合流：通过 docs/adr/0002-coordinate-main-delivery-with-merge-trains.md 机制，多个已就绪的任务排入合流队列，逐一获取 Merge Lease 执行合流，杜绝主干冲突。
04

安全模型与沙箱局限性深度审查

安全层级 已实现的防御措施 官方明确指出的局限性 (Known Gaps)
主体权限隔离 Operator / Runner / Session 三级主体分离；Session Token 随 Run 结束即销毁。 多 Runner 仍共享宿主机器环境，若使用相同用户账户运行，无法实现物理级强隔离。
密钥管理 敏感配置与 Secret 使用 AES-256-GCM 加密存储，API 输出自动脱敏。 子进程环境中直接注入明文 Secret，若 Agent 被 Prompt Injection 仍可能打印凭证。
文件系统授权 Filesystem Grants 限制 API 访问的 Files Root。 非 OS 级沙箱：Provider CLI 携带了权限绕过参数，Grants 属于 API 审计层，而非内核文件系统拦截。
网络隔离 支持 RUNNER_HTTP_PROXY 显式代理拦截。 未实现强制网络隔离，子进程可直接访问本地局域网与其他未受保护服务。
05

批判性工程审视 (Critical Review)

✅ 突出设计优势 (Engineering Strengths)
  • 异构模型协同与双盲评审：打通 Claude Opus、GPT-5.6 与 Pi，通过第 6 步与第 7 步的两次独立双盲代码审查，极大抑制了单一模型的逻辑幻觉与自我盲信。
  • 真正的 Spec-to-Merge 闭环：配合 Merge Train 与独立回归验证，真正实现了无人值守从需求到 PR 合并的高吞吐。
  • 零 API Key 转发风险：直接以子进程调起开发者本机已登录的官方 CLI，不碰用户账号凭据，免去中间代理费用。
  • 严谨的分布式并发控制：基于 PostgreSQL + Prisma 的 Fencing Generation 租约机制，具备良好的防脑裂与僵尸进程处理能力。
⚠️ 潜在架构瓶颈与风险 (Bottlenecks & Risks)
  • 系统复杂度与部署负担重：需要常驻 Node.js 22+ 环境、PostgreSQL 数据库、Hono API 服务、Vite 前端与 Runner 守护进程，无法像轻量 Skill 那样秒级即装即用。
  • 缺乏 OS 层强沙箱隔离：官方明确说明目前为 API 级授权，无内核沙箱或容器隔离，不可轻易用于执行不可信第三方代码。
  • 高度依赖本地 CLI 的稳定性：官方 CLI 的版本变动、Rate Limit 额度耗尽或登录态过期，会导致整个本地流水线产生连锁阻塞。
  • 平台兼容性初期局限：目前主要标定为 macOS Apple Silicon (Developer Preview)，Linux/Windows 的适配与容器化支撑尚处于演进阶段。
06

架构形态深度对比：Anneal vs YY-Flow

核心维度 Anneal (外部调度平台型) YY-Flow (宿主内嵌技能型)
运行载体 外部独立系统 (Node.js + PostgreSQL + Vite Web + Runner) 宿主内嵌技能 (Markdown 规约 + 8 大 Subagents + Python CLI)
交互核心 无人值守吞吐：人类在 Web 提 Spec，链自动清空看板并合流 人机协同防错：分级三问网关、8 专家交叉制衡、人工专属终验
审查机制 工步切片式：GPT 审查 + Claude Opus 双盲独立审查 拟人角色制：周审查 (Reviewer) + 章测试 (QA) 门控与自愈打回
合流策略 自动 Merge Gate + Merge Train 抢占合流 工作区物理隔离，严禁 Agent 擅自 Commit/Merge，人类最终确认
适用场景 规格高度结构化、追求大批量无人值守切片交付的独立研发流 强调研发过程合规、文档沉淀、交互式结对与严密防错的企业级协同
07

决策摘要与结论

📌 架构分析核心结论

Anneal 代表了 Coding Agent 向“重型外部调度平台与全自动无人值守流水线”演进的典型范式。其最大的工程亮点在于跨异构模型编排（Claude+GPT+Pi）、双盲独立代码审查与 Fenced Lease 租约防脑裂并发控制。尽管其部署依赖较重且缺乏 OS 级内核沙箱隔离，但其在“将 Spec 自动化交付至 Merge”的流程设计上为多 Agent 自动化研发提供了极具参考价值的工业化范式。
